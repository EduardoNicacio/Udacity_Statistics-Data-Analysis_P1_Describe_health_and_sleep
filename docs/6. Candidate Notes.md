## 1. Elevator Pitch

**The Problem:** A slide deck has to report four things about the Sleep Health and Lifestyle Dataset - one example of each variable type, the typical amount of daily physical activity, the spread of daily steps, and the shape of the heart-rate distribution with any outliers - and every number on those slides is graded against a rubric for correctness. Hand calculations invite transcription errors; ad-hoc notebook cells invite numbers that disagree between the console and the deck.

**The Solution:** A single reproducible script, `sleep_analysis.py`, executes the project brief in order: it downloads the CSV from the Udacity CDN with `requests` and verifies the file is non-empty, loads it with pandas, prints the standard inspection suite (`head`, `shape`, `dtypes`, `describe`, `isnull`), classifies one variable of each type with a written justification, computes measures of center and spread rounded to two decimal places, and renders a 15-bin histogram with a KDE overlay and dashed mean/median lines before writing every result to `analysis_summary.txt` under headers that match the four slide names.

**The Result:** The dataset holds **374 rows × 13 columns** with 219 blank `Sleep Disorder` cells. `Physical Activity Level` averages **59.17** minutes/day with median **60.00** and mode **60.00** (n = 70) - an approximately symmetric distribution, since mean ≈ median. `Daily Steps` has standard deviation **1617.92**, range **7000** (3,000-10,000), IQR **2400**, and variance **2,617,651.14**. `Heart Rate` centers on **70.17** bpm (median **70.00**); the 1.5×IQR rule (fences **62.00** / **78.00**) identifies **15 outliers between 80 and 86 bpm**, and the distribution is right-skewed (skewness **1.22**) with a secondary cluster in the mid-70s. Every figure was independently recomputed in a second implementation and matched exactly.

## 2. Architecture & Analysis Design

### Analysis Pipeline

```txt
┌─────────────────────────────────────────────────────────────────────────────┐
│ Source - Sleep Health and Lifestyle Dataset (Udacity CDN, Kaggle uom190346a)│
│ 374 rows x 13 columns · 219 blank 'Sleep Disorder' cells                    │
│ requests.get → sleep_health.csv (24,137 bytes) → pd.read_csv                │
└──────────────────────────────┬──────────────────────────────────────────────┘
                               ▼ Step 2 inspect (head / shape / dtypes / describe / isnull)
┌─────────────────────────────────────────────────────────────────────────────┐
│ Continuous : Sleep Duration (float hours, e.g. 7.2)                         │
│ Integer    : Daily Steps (whole-number count)                               │
│ Ordinal    : Quality of Sleep (ordered 1-10 rating)                         │
│ Nominal    : Gender (unordered Male / Female labels)                        │
└──────────────────────────────┬──────────────────────────────────────────────┘
                               ▼ Step 4 center → Step 5 spread → Step 6 plot
┌─────────────────────────────────────────────────────────────────────────────┐
│ PAL  : mean 59.17 · median 60.00 · mode 60.00 (n = 70) → symmetric          │

│ HR   : histplot(bins=15, kde=True) + mean/median vlines                     │
│        fences 62.00/78.00 → 15 outliers (80-86 bpm), skew 1.22 right-skewed │
└──────────────────────────────┬──────────────────────────────────────────────┘
                               ▼ Step 7 store
┌─────────────────────────────────────────────────────────────────────────────┐
│ analysis_summary.txt      - four sections: "Slide: Data Description",       │
│                             "Slide: Typical Physical Activity (Minutes)",    │

│ heart_rate_distribution.png - 150 dpi, 9 x 5.5 in figure                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Key Design Decisions

| Decision | Rationale |
| :--- | :--- |
| **Verify the download before anything runs** | `response.raise_for_status()` plus an explicit `len(content)` check and a second `os.path.getsize` guard mean an empty or failed download aborts loudly instead of producing an empty DataFrame and a silently wrong deck. Re-runs skip the download when a non-empty CSV is already present, so the pipeline is idempotent without ever reading a zero-byte file. |
| **Classify by measurement level, not by dtype** | `Quality of Sleep` is stored as `int64`, yet it is an *ordinal* categorical variable because the 1-10 scale carries a natural order; `Daily Steps` is an integer but its meaning is a discrete count. The justifications in the output state the reasoning, not just the pick - which is what the rubric actually grades. |
| **Round only at output time, through one helper** | All arithmetic runs at full precision; `f2()` applies `:.2f` exclusively when text is produced. Rounding earlier would compound - for example, the variance 2,617,651.14 would drift if the underlying sums were pre-rounded, and the rubric's two-decimal rule would still have to be met at the end. |
| **Interpret skew from the data, not from a template** | The `Physical Activity Level` verdict is computed by comparing mean (59.17) to median (60.00) against a 5% relative threshold; the heart-rate description is driven by the computed skewness (1.22) and then corrected against the actual histogram. No shape claim is hardcoded. |
| **State the outlier rule explicitly** | Outliers are defined as the rubric specifies - below `Q1 - 1.5×IQR` or above `Q3 + 1.5×IQR` - and both fences (62.00 / 78.00) are printed next to the values they flag. A reader can reproduce the 15 outliers by hand from the printed quartiles. |
| **Build the summary text programmatically** | Each section is assembled from the same variables that feed `print()`, so `analysis_summary.txt` cannot drift from the console output. Capturing stdout instead would be fragile across platforms and encodings. |
| **Headless-safe plotting** | `matplotlib.use("Agg")` before pyplot import, `figsize=(9, 5.5)`, `tight_layout()`, and an explicit `dpi=150` in `savefig` make the PNG identical on a workstation, a CI runner, or a server without a display. |
| **Keep raw and derived artifacts separate** | `sleep_health.csv` is stored byte-for-byte as downloaded; `analysis_summary.txt` and `heart_rate_distribution.png` are derived. The distinction lets a reviewer re-run the analysis against the original bytes. |

## 3. Analytical Principles in Practice

**Separate description from interpretation - and label both.** Every slide number is a description (mean 59.17, range 7000, 15 outliers); the sentences that follow are interpretation ("approximately symmetric because mean ≈ median"). The output keeps them in distinct lines so the deck can quote either without conflating them.

**Let the mean/median relationship answer the rubric's standout question.** For `Physical Activity Level`, mean 59.17 sits 0.83 below median 60.00 - within 5% - so the distribution is called approximately symmetric. The computed skewness of 0.07 confirms the verdict independently rather than the threshold alone asserting it.

**Report multiple measures when asked for one.** The brief asks for mean, median and mode (three center measures) and for standard deviation, minimum, maximum and range (four spread measures); the analysis adds IQR and variance as bonus spread measures, each rounded to two decimals, so the deck can show more than the minimum without re-running anything.

**Define outliers by a stated rule, never by eye.** The heart-rate plot shows bars between 80 and 86 bpm that a casual reader might dismiss; the printed fences prove they are genuine outliers *relative to this dataset's tight IQR of 4.00 bpm*. The wording deliberately says "outliers in this dataset," not "abnormal heart rates" - the 1.5×IQR rule is a distributional test, not a clinical one.

**Describe shape from the evidence, including the inconvenient parts.** Skewness alone would have produced "right-skewed, done." The histogram shows a second cluster of elevated rates around 75 bpm, so the final description says the shape is *not perfectly unimodal* as well as right-skewed - the rubric asks "what is the shape," and an honest answer names the bump.

**Disclose missingness instead of papering over it.** 219 of 374 `Sleep Disorder` cells are blank; per the dataset documentation these mean "no disorder recorded." The Data Description slide states the count and the interpretation rather than silently treating the column as complete - and no imputation is performed on a column the analysis never uses.

**Descriptive statistics are not causal claims.** Nothing in this project says physical activity *causes* better sleep quality; the numbers describe this sample of 374 people only, and the summary is written so the deck can quote them without implying otherwise.

## 4. AI Collaboration Playbook

The deliverable was a slide deck whose every figure had to match a reproducible computation, so the workflow was built around an evidence hierarchy: **source CSV → executed script → summary text → slide deck**.

The workflow was:

1. **DeepSeek V4.1 drafted the seven-step script directly from the project brief** - download, inspect, classify, center, spread, plot, summarize - as one linear, re-runnable file, with all calculations done in pandas/scipy and all outputs written to the working directory.
2. **MiMo reviewed the complete artifact against `docs/5. Rubric.md` criterion by criterion**, treating the rubric as the specification: correct values, correct variable types, center/spread present when asked, plot + outliers present.
3. **Every number was recomputed in a second, independent implementation** - Python's `statistics` module plus hand-written linear-interpolation quartiles over the raw CSV - instead of re-reading the script's own outputs. Agreement between two independent computations is the check; agreeing with yourself is not.
4. **Formatting defects found in review were fixed and the script was re-run end-to-end**, not patched in place: the final file is a clean full execution (fresh PNG, fresh TXT, matching console).
5. **The written narrative (README and these notes) was checked back against `analysis_summary.txt`**, so no prose number exists that the executed script did not produce.

The key collaboration principle is **verify, don't trust**: the reviewing model never accepted a figure because the drafting model asserted it - it recomputed it - and the drafting model never guessed at the data's shape because the brief said to describe it.

## 5. Evaluation & Verification Philosophy

**Executed outputs are the evidence.** All reported figures - 374 rows, mean 59.17, mode count 70, SD 1617.92, variance 2,617,651.14, the 62.00/78.00 fences, 15 outliers, skewness 1.22 - were read from a completed run of `sleep_analysis.py`, not estimated or recalled.

**Two independent implementations beat one careful one.** The verification pass re-derived every statistic from the raw CSV with different tools (`statistics.stdev` for sample standard deviation, a manual `(n-1)·q` quartile interpolator matching the spreadsheet `QUARTILE` convention) and required exact agreement at two decimals before the rubric could be marked satisfied.

**Check the rubric against the artifact, not against the intent.** The review below walks the four rubric criteria and the two standout suggestions one by one against what actually exists in `analysis_summary.txt` and `heart_rate_distribution.png` - the same discipline as checking a notebook cell by cell.

**Denominators belong next to every count.** "Mode 60.00 occurs 70 times" is only meaningful as 70 of 374 (18.7%); "15 outliers" means 15 of 374 values (4.0%) above the 78.00 fence. The output prints the sample size beside every statistic.

**Rounding is a presentation rule, not a computation rule.** The rubric demands two decimals on floats; the script therefore rounds once, at output, and the verification pass confirms the rounded values match - so the deck's numbers and the script's numbers are the same numbers.

**The dataset's limits are disclosed, not hidden.** The 219 blank `Sleep Disorder` cells, the rounded step counts (20 distinct values from 3,000 to 10,000), and the clustered activity levels are all characteristics of this particular dataset; noting them keeps the deck's claims proportional to the data behind them.

## 6. Challenges & Resolutions

### Challenge 1 - 219 blank Sleep Disorder cells

**What happened:** `df.isnull().sum()` reports 219 missing values - the only missingness in the dataset, and the first thing a reviewer notices. A naive `dropna()` would have deleted 58.6% of the rows for a column the analysis never uses, while silently claiming the dataset was "clean."

**Resolution:** Per `docs/2. Dataset Details.md`, a blank means "no disorder recorded" (`None`), so the rows are kept untouched. The Data Description slide states the count and its meaning explicitly - "219 in total, found in 'Sleep Disorder'" - turning an apparent data-quality problem into a documented characteristic. No imputation was performed because no calculation depends on the column. The figure is 219/374 = 58.6% of records, which makes the disclosure mandatory rather than optional: a `dropna()` shortcut would have silently cut the sample to 155 rows.

### Challenge 2 - Two-decimal formatting drifted between runs

**What happened:** The first full run satisfied "round all floats to 2 decimal places" inconsistently: the console printed `Median : 60.0` and `Minimum : 3000.0`, the legend read `Median = 70.0 bpm`, the outlier fences appeared as `[62.0, 78.0]`, and one sentence concatenated two clauses without punctuation ("...toward the right Outliers exist:..."). Each defect alone was cosmetic; together they would have produced a deck with numbers in three different formats.

**Resolution:** A single `f2()` helper (`f"{float(value):.2f}"`) now formats every value destined for text or a label, replacing ad-hoc `round()` calls, and the shape/outlier sentence is assembled with an explicit separator. The script was re-run end-to-end and the final `analysis_summary.txt` was re-read line by line to confirm uniform two-decimal formatting throughout.

### Challenge 3 - The heart-rate shape is not a simple bell

**What happened:** Skewness of 1.22 alone would have justified the one-line answer "right-skewed." The rendered histogram shows something more specific: a dominant peak in the high 60s, a near-empty gap, and a secondary cluster of bars around 75 bpm before the long tail of 80s. Describing only the skew would answer the rubric's question incompletely.

**Resolution:** The final description combines both observations - "right-skewed (positively skewed, skewness = 1.22)... and the shape is not perfectly unimodal - a secondary cluster of elevated rates sits in the mid-70s bpm next to the main peak in the high 60s." The claim was written *after* reading the generated PNG, not before.

### Challenge 4 - The IQR rule flags heart rates that look ordinary

**What happened:** The heart-rate IQR is only 4.00 bpm (Q1 68.00, Q3 72.00), so the upper fence lands at 78.00 bpm and flags 15 people whose rates (80-86 bpm) are unremarkable in clinical terms. Reporting "15 abnormal heart rates" would misrepresent what the rule tested; omitting them would fail the rubric.

**Resolution:** The output states the rule, both fences, the count, and the flagged values verbatim, and the interpretation is scoped to the dataset: outliers *relative to this distribution*. The distinction keeps the statistical claim (values beyond 1.5×IQR) separate from any medical claim the data cannot support.

### Challenge 5 - Rounding too early would contaminate every downstream figure

**What happened:** The brief demands two-decimal output, and the obvious shortcut - round on read - would corrupt the analysis: pre-rounded steps would change the variance (2,617,651.14 requires full-precision sums), and the IQR fences (62.00 / 78.00) depend on exact quartiles. A rounding decision made for presentation would have silently altered the statistics being presented.

**Resolution:** Arithmetic runs at full precision end to end; rounding happens exactly once, inside `f2()` at the point text is produced. The independent verification pass - computing from the raw CSV with a separate implementation - confirmed the rounded outputs are correct *as roundings of the true values*, not of intermediate approximations.

## 7. Review & Refinement

The principal refinement was **reconciling the artifact against the rubric with an independent recomputation**: every statistic in `analysis_summary.txt` was re-derived from `sleep_health.csv` using Python's `statistics` module and a hand-written quartile interpolator, and all values matched at two decimals - PAL mean 59.17 / median 60.00 / mode 60.00 (count 70), steps SD 1617.92, variance 2,617,651.14, min 3000, max 10000, range 7000, Q1 5600, Q3 8000, IQR 2400, heart-rate mean 70.17, fences 62.00/78.00, 15 outliers at 80-86 bpm, skewness 1.22.

A second pass fixed the presentation defects found in review: uniform two-decimal formatting everywhere (`60.0` → `60.00`, `3000.0` → `3000.00`, legend `70.0` → `70.00`, fences `[62.0, 78.0]` → `[62.00, 78.00]`), the malformed shape sentence (missing separator and duplicated outlier clause), and an enriched heart-rate shape description that names the secondary mid-70s cluster visible in the final PNG. A missing-data disclosure line was also added to the Data Description section so the 219 blank cells appear in the deck-ready summary rather than only in the console.

One deliberate trade-off is worth recording: the rubric grades the *slide deck*, and the course materials allow any tool (spreadsheets, calculators, AI). These notes and the README therefore quote only figures that a second implementation reproduced from the raw CSV - so any number pasted into the deck can be defended by re-running either implementation, not just the original script.

The final review re-checked every rubric criterion against the executed artifact rather than the intent: all statistical values computed correctly (independently verified), variable types correctly identified with justifications (one of each: continuous, integer, ordinal, nominal), measures of center provided when asked (mean, median, mode) and measures of spread when asked (SD, min, max, range, plus IQR and variance), the heart-rate distribution plotted with outliers identified (15-bin histogram + KDE, dashed mean/median lines, 15 IQR outliers listed), and both standout suggestions addressed (mean-vs-median shape interpretation for physical activity; multiple center and spread measures throughout). **No issues were found that block submission**; the remaining work is transferring the four sections into the slide deck.

## 10. Retrospective

### What I'd Do Differently

1. **Cross-check with a spreadsheet, as the course suggests.** `docs/4. Tools and Resources.md` explicitly invites computing the same statistics in Google Sheets (`AVERAGE`, `MEDIAN`, `MODE`, `STDEV`) to confirm consistency. I verified with a second Python implementation; a third, human-visible tool would close the loop the course intended and make the numbers auditable without running code.
2. **Add a box plot beside the histogram.** The 15 outliers are currently proven numerically (fences + values); a box plot would show the same fact visually and make the tight 4.00 bpm IQR obvious at a glance - one extra `sns.boxplot` call for a stronger "are there outliers?" slide.
3. **State the quartile and standard-deviation conventions in the output.** pandas' linear-interpolation quartiles and the sample standard deviation (ddof = 1) match spreadsheet conventions, but printing "sample SD (ddof = 1), quartiles by linear interpolation" would preempt a reviewer asking why `describe()` and `statistics.pstdev` disagree.
4. **Report the mode's plurality honestly across tied groups.** The activity levels 30, 45, 60, 75 and 90 each appear 67-70 times; 60 wins by three records. Saying "mode 60.00 (n = 70)" is correct, but noting the near-tie would prevent over-reading the mode as a strong signal.
5. **Extend from description to inference.** This project stops at descriptive statistics by design, but the natural next step is comparing heart rates or steps between groups (e.g., by `BMI Category`) with confidence intervals - turning "the sample mean is 59.17" into "the population mean is likely in this range."

### What Worked Well

1. **Independent recomputation as the review mechanism.** Re-deriving every figure from the raw CSV with `statistics` + manual quartiles - rather than re-reading the script's own output - is what turned "looks right" into "verified against two implementations," and it caught no value errors, which is exactly the assurance the rubric's first criterion needs.
2. **One formatting helper for the two-decimal rule.** Centralizing output formatting in `f2()` eliminated the `60.0` / `70.0` / `[62.0, 78.0]` drift in one edit and makes the presentation rule impossible to forget in future code.
3. **Idempotent download with two non-empty guards.** Re-running never re-downloads a good file, never reads a zero-byte one, and fails loudly if the source does - the script has been executed three times end to end with identical results.
4. **Building the summary from the same variables as the console.** Because `analysis_summary.txt` and the printed output share one source of truth, the deck-ready file cannot disagree with what was actually computed.
5. **Reading the PNG before writing the prose.** Catching the secondary mid-70s cluster in the rendered figure changed the shape description from a template line to an evidence-based one - the rubric asks what the shape *is*, and the plot answered better than the skewness statistic alone.
6. **Disclosing the 219 blanks instead of dropping rows.** Keeping the full 374 observations and documenting the missingness preserved statistical power and turned the only data-quality issue into a stated fact on the Data Description slide.

### The AI Partnership

> "The value of the AI partnership here was a division of labor the rubric rewards: DeepSeek V4.1 translated the seven-step brief into a working, re-runnable script; MiMo treated the rubric as the specification, recomputed every number from the raw CSV with a second independent implementation, and refused to accept a figure merely because the first model asserted it. That review found no arithmetic errors - the statistics were right - but it did find presentation defects a grader would see immediately: floats printed with inconsistent decimals, a malformed sentence, a legend label that disagreed with its own table, and a shape description that was true but incomplete. The lesson is that correctness has two layers - the value and its presentation - and only one of them gets checked automatically. The human role was to demand the second implementation, to insist the shape claim be read off the actual plot, and to keep the interpretation proportional: outliers relative to a 4.00 bpm IQR, symmetry within a clustered discrete variable, and descriptive statistics that describe - not explain - 374 people."

### Final Thoughts

I followed the project's core discipline end to end: download and verify the source, inspect before classifying, classify variables by measurement level with written justification, report multiple measures of center and multiple measures of spread exactly as asked, interpret mean-versus-median as the rubric's standout question invites, and plot the heart-rate distribution with its outliers identified by a stated rule. The result is four slide-ready sections in `analysis_summary.txt` whose every figure was reproduced by a second implementation.

The most useful engineering lesson is the one the formatting pass taught: **a correct number in the wrong format is still a review finding.** Statistics that satisfy the arithmetic rubric can still fail the presentation rubric if the deck shows `60.0` on one slide and `60.00` on another - so rounding was centralized, the summary was generated from the same variables as the console, and the final artifact was read line by line rather than assumed correct because the computation was.
